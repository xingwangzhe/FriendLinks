# dev 数据采样配置

## 调整数量

`astro.config.mjs` 顶部的 `DEV_SAMPLE_SIZE` 默认值为 100。启动环境变量优先于该常量；未设置环境变量时使用常量。

```bash
DEV_SAMPLE_SIZE=100 bun run dev
DEV_SAMPLE_SIZE=500 bun run dev
DEV_SAMPLE_SIZE=0 bun run dev
```

0 表示加载全部正式站点，正整数表示抽样上限，超过数据集数量时加载全部。值必须为非负安全整数（最大 9007199254740991）；环境变量仅接受十进制数字字符串，空字符串、空白、负数、小数、非数字和超出安全范围的值会在启动时报错。修改配置或环境变量后需要重启开发服务器。

## 数量的含义

配置限制正式站点抽样数量，不保证最终星球总数。正式站点的友链目标仍可能生成额外节点与连线。`links/unverified/` 继续排除；配置不改变准入规则。

Astro 通过 Vite `define` 将值注入 `__DEV_SAMPLE_SIZE__`。`src/utils/sample.ts` 将 0 转为无限上限，两个加载入口共享该配置：`sites.ts` 在解析和校验后采样，`load-sites.ts` 在读取 YAML 正文前限制文件数。因此存在无效 YAML 时，两者返回数量不一定相同。

采样沿用现有算法。本配置不改变节点排序、图关系、端点格式或客户端 API。

## 全量与生产模式

全量 dev 仍使用现有 dev 力导模拟和数据传输方式，不自动切换生产计算参数。加载全部数据可能显著增加 IO、内存和空间布局耗时。

生产模式不会应用 dev 抽样上限，始终加载全量正式站点；配置值仍会在 Astro 配置加载时校验。生产构建耗时较长，代理未经用户明确授权不得执行。

## 验证与维护

优先使用 `bun run lint` 和格式检查。启动 dev 后可检查 `/all.json` 的数组长度，验证正式站点抽样；不要将图节点总数当成同一个指标。全量语义宜使用小型测试数据验证，避免为配置测试计算真实全量图。


## 前端控件与浮动面板

界面统一使用 Tailwind CSS v4 与 daisyUI 免费组件。按钮、输入框、滑块、开关、加载状态和统计卡片均采用原生 HTML，可叠加 Tailwind 工具类。

统计、关于、控制、邻居和路径查找使用原生 `<dialog>` 非模态面板，不依赖第三方窗口库。控制、邻居靠右，统计/关于为宽面板，路径查找为底部 dock；移动端统一为底部 sheet。关闭按钮或 Escape 关闭并返回入口焦点，内容在面板内部滚动，背景宇宙仍可交互。

飞船模式只使用底部 HUD：半透明淡文字、`pointer-events: none`、不获取焦点；`X` 使用高亮提示退出。

开发验证使用 `bun run dev` 的抽样数据，运行 `bun run lint`、`bun test`、`bun run verify:controls` 与改动文件格式检查；浏览器验收覆盖面板开关、鼠标只转向、WASD/RF 位移、Shift 加速、Q/E 横滚、X 退出、速度滑块和静止停绘。开发模式会清理本项目旧 Service Worker 缓存，避免加载过期控件代码。不得以生产构建替代 dev 检查。
