# 站点身份、相似地址与重复 YAML 策略

`site.url` 是逻辑站点的规范入口；可选的 `site.aliases: string[]` 声明有证据确认属于同一站点的旧地址、镜像或其他入口。已有 YAML 无需填写 aliases。别名不会联网探测，也不会启用 outdated 中的审核工具。

```yaml
site:
  name: HeyBlog
  description: 独立博客发现与目录
  url: https://www.heyblog.net/
  aliases:
    - https://www.zhblogs.net/
  links: /site
  friends: [] # 仅为格式示例；迁移时保留实际友链
```

## 相似只是线索，证据决定同义关系

本策略区分三件事：筛选相似候选、确认地址身份、整理重复文件。只有确认属于同一逻辑站点后，才声明别名或合并跨域记录。不能根据站名、相似域名、同一作者、同一注册域、相同框架或主题推断同义关系。身份确认也不能替代 AGENTS.md 对个人文字博客的准入、降级与排除判断。

| 候选或证据 | 可以支持的结论 | 需要排除的歧义 |
| --- | --- | --- |
| 主地址规范化后完全相同 | 已是同一入口，可直接整理重复 YAML，无需重新联网推断 | 文件名相似不等于主地址相同；不同栏目不自动合并 |
| 旧入口跳转到规范站点，目标真实内容可读 | 旧入口与最终入口的迁移关系 | 不能把共同跳到停放页、验证页、错误页或平台首页当作同站证据 |
| 站点声明相同 canonical，且内容与发布入口对应 | 规范入口及镜像或迁移关系 | 检查是否复制了模板 canonical，是否指向独立语言站或其他栏目 |
| 发布者公告、旧域名说明或明确的镜像声明 | 公告覆盖范围内的别名关系 | 同品牌的多个服务、域名展示页与实际博客目录可能是不同功能 |
| `www` 镜像的文章目录、正文、作者说明与站内链接一致 | 经逐项复核后可确认同一站点的镜像 | 相同标题、主题、模板文或通用验证页不够；不能扩展到未检查的子域名 |
| 同名、相似域名、相同社交账号、相同内容片段 | 调查候选 | 可能是同作者的独立博客、语言站、分支栏目或转载采集站 |

不设置“相似度达到多少就自动合并”的阈值。临时统计脚本可以按主地址、别名、友链中的 hostname、站名和域名主体筛选、排序候选；评分只影响复核顺序。应说明扫描范围、候选类别重叠，以及本轮实际检查了哪些候选，不能把选中的一批说成全库已核实。

没有正式记录的外部友链目标可以成为调查候选，但不能仅为减少节点而创建空 `friends` 占位。若需新增正式站点，先按准入标准验证；访问失败或归属不明保存待复核证据，不新增 aliases。此前已经存在的记录，本轮只确认或拒绝新同义关系，不凭一次失败直接删站。

## 维护流程与文件合并

1. **统计与筛选**：递归扫描正式 YAML 的主地址、aliases 和友链，默认排除 `unverified`。区分原始引用数、唯一地址数和候选组数；避免把含凭据的 URL 写入公开报告。
2. **用 `crwl` 复核**：保存请求地址、最终地址、状态、canonical、检查日期及 Markdown。遇到异步加载的文章流，可增加等待时间或继续检查索引及一篇正文；空首屏不直接判定为无内容。对跨域迁移和混合用途，核对公告、作者说明及实际发布入口。
3. **确认规范入口**：保留规范地址的正确范围；综合站的独立博客栏目使用栏目 URL。明确哪些旧入口或镜像属于它，哪些语言站、栏目或子服务仍独立。新地址的名称与友链路由依据当前页面更新，并保留旧元数据说明。
4. **先建立完整身份映射**：按照下述规则合并逻辑记录，冲突或迁移环立即失败。不得仅删掉“看起来重复”的文件，也不得因某文件友链较少就丢弃其独有关系。
5. **整理为一份 YAML**：保留主记录，合并 aliases 和 friends，随后删除被合并文件。普通文件以规范主 URL 的 hostname 命名；同 hostname 有多个独立栏目时保留不同文件路径，不能覆盖或为统一文件名强行合并。保存各来源文件、原元数据、采集说明及证据路径。
6. **校验并比较**：运行 `bun run validate` 与修改文件的格式检查。只整理已合并的重复文件时，合并后的逻辑记录及纯拓扑应逐项相同；新增别名时，将原关系按最终身份重新解析、去重并排除内部自引用，与新拓扑比较缺失及额外关系。涉及身份代码时再运行 lint 与相关测试。

临时脚本完成后清理；候选清单、复核决定、证据和合并统计保留为报告。构建不联网探测，不启用 `outdated/` 中已弃用的过滤审核工具。不执行力导布局或全库 BFS 来验证文件去重；未经明确授权不执行生产 build，也不自动提交或推送。

## 逻辑合并及地址匹配规则

同一规范地址的重复记录自动合并。声明方 aliases 包含另一记录的主地址时，该记录迁至声明方；无环的多级迁移最终使用终点记录。相同主地址以相对文件路径排序，首份提供元数据，缺失的颜色、图标、友链路由从后续记录补齐，路由最终默认 `/links`。名称、描述等差异输出提示。迁移终点记录优先于旧记录。

各记录的友链取并集，先按身份解析目标，再去重并去掉内部自引用。重复目标以主记录的友链信息优先，其他按稳定文件顺序取首份。并集表示仓库已有关系的保留，不证明历史友链仍有效。

地址匹配规则：

- HTTP/HTTPS 与片段不区分身份；非默认端口区分。不同 hostname，包括 www，必须显式声明别名。
- 根入口覆盖同 host 的路径；栏目入口覆盖自身与下级路径，以路径段边界匹配，最长入口优先。`/blog` 不覆盖 `/blogger`。
- 有查询参数的入口只匹配自身路径及完全相同的查询字符串，不覆盖下级路径。查询参数顺序不自动重排。
- 所有正式主入口和别名均参与匹配，不按站名、注册域或相似域名推断。
- 未匹配外部目标按 host 聚合；当该 host 已对应多个逻辑栏目时，使用规范化完整 URL 作为外部节点 ID，避免将不同栏目强行合并。

## 共享拓扑、采样与缓存

两套加载入口使用 `site-collection.ts` 和 `site-identity.ts`，先读取完整正式集合、解析身份并合并，再确定性抽样。采样保留完整身份映射，因此被抽样省略的站点仍可作为规范目标识别。目录和采样上限分别作为缓存键，站点缓存清理同时失效身份和拓扑缓存。

`graph-topology.ts` 只生成节点、去重有向关系、单/双向边以及邻接表，不做布局或 BFS。图二进制、统计与六度工具复用该拓扑；互指关系合为一条双向边，其余为单向边。六度工具包含外部节点，路径查询支持规范 URL、别名 URL 和可唯一归属的 hostname；同域多栏目宜使用完整 URL。

## 数据输出与原始计数

`/all.json` 输出合并记录，含整理后的 aliases 和规范化友链。统计原有字段依据逻辑节点与去重关系；`totalFriendReferences` 是合并后友链数量，`sourceRecords` 保留原始计数：

| 字段 | 意义 |
| --- | --- |
| rawRecords | 当前集合对应的原始 YAML 记录数 |
| mergedRecords | 原始记录数减逻辑站点数 |
| rawFriendReferences | 上述原始记录的友链引用总数，含重复与自引用 |
| totalRawRecords | 抽样前全目录原始记录数 |
| totalLogicalSites | 抽样前全目录逻辑站点数 |

## 校验、验收与性能口径

共享 Zod Schema 位于 `site-collection.ts`。格式错误、别名冲突及迁移环都会使 `bun run validate` 非零退出，报告文件及地址。正式加载也会失败，不会静默跳过错误记录。`links/unverified/` 仍默认跳过。

验证使用 `bun run lint`、`bun test src/utils/site-identity.test.ts` 与 `bun run validate`。未经授权不运行生产 build；拓扑减少量不等于已测量的构建耗时改善。

实体文件合并与图身份合并应分别报告。若加载器原本已经把两份 YAML 折叠成一份逻辑记录，删除重复 YAML 只减少文件读取与维护，不会再次减少图节点或边。新增已确认别名可能缩小拓扑，但修正栏目归属也可能增加此前被错误折叠的关系。报告实际数量，不把候选数量或重复文件数量等同于性能收益。

2026-10-02 的记录仅作为有日期的验证快照：相似地址复核后，逻辑站点为 8589、纯拓扑节点为 49322、边为 108348；继续整理 33 组同入口 YAML 后，正式文件也为 8589，逻辑记录与拓扑逐项不变。当前数量以仓库数据和数据端点为准。
