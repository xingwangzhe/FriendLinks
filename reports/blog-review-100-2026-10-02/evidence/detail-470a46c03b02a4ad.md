# ai agent，一些杂谈
发表于 2026-08-16
2.9k- 9m--[](https://misakishiki.site/posts/792209865.html#comment)
[杂谈](https://misakishiki.site/tags/%E6%9D%82%E8%B0%88/)
一些vibe coding的心得。
类似日记吧。
对于现在的AI，我其实没有那么看好。
要不是claudecode跑通了编程环节，给AI续了一波命，很难说现在会是一个什么情况。
稳定可盈利的路线已经有了，但是coding层面肯定还是不够的。
所以最近经常能看到各方面的数学医学基础学科的AI发展，但其实也是饮鸠止渴，因为这些成果虽然很牛逼，但的确是赚不到多少钱。而且很多时候也不够强，最先应该是GPT朝这方面走，出了一个据说是能发四大的这个证明，之后claude跟上。
国模呢，依旧是在走coding的路子，稳步发育。
当然AI rp的市场其实很大，但多少有点上不了台面了，一方面是不够星辰大海，撑不起这么高的市值幻想，现在coding方面和基础学科方面的进步，可以说是自我进化的一部分，就比如说在大秦成为炼制不死仙丹的方士，虽然我们不死仙丹炼不出来，但是把食物药物的制作工艺提上来，肯定是有效果的。
另一方面就是付费意愿了，文字内容生成这东西，即便优化了，大伙肯定还是愿意选便宜的多抽卡。coding是为了创造更多的利益，公司给自家职工报销，然后跑通这一整个环节，很现实很直观，所有人都能看懂。但是AI rp不太行，精神食量这一块。就哪怕真有这种模型，卯足了劲赚钱，估计也就是一个番茄或者起点的水平。尤其是现在视频和网文和各种各样的东西越来越多的前提下，
不过这个猜字词的架构还是挺不错的，AI的确适合预测规律方面的内容，对于绝大多数需要复杂计算的内容，AI可以说都是最优解。
最开始接触到 vibe coding 是群友给的咸鱼套餐。20块一个月，每天一百刀，当时爽蹬 codex，做出了第一版 demo，demo0.5。
三月二十七。
当时是单纯想试试 ai 能做到什么地步，于是打算做一个游戏。毕竟虽然claudecode跑出来了，但对实际的
当时 demo 的各方面都比较粗糙。
内容也不多，只是一个基础的大概框架。所以蹬了两天差不多就蹬完了。
看上去就像是什么军旗软件。
最初做的是四边形的，城池也是很简单的按照 Ai 的设计，摆铺在两边，至于二级菜单什么的几乎一个也没有。
之后改成六边形了，给地格增加了具体的颜色。还有士兵的大致素材靠代码 draw 出来。
至于为什么不继续用，那当然是链接下架退款了。薅注册机的人虽强，但奥特曼的剑也未尝不利。
那时候我只听说注册机被打压了好一部分，还没意识到 Ai 厂商的 token 额度收缩寒潮即将加速到来。
在那之后我便寻求着别的办法，codex 当时免费用户还有周的两倍额度，我靠着这个周额度，又用了一段时间。
不过在这么下去，开发进度估计要被进一步推迟。
于是在群友的帮助下我尝试领取了 github 上免费送的 copilot pro。
说实话，这真是我用过最好的 ai 服务了，又有 opus 又有 5.4，而且使用还是按次数计算的。
性价比这块非常无敌。
不过由于我开的时间是月底，所以额度刷新的那天我熬夜框框用，也没能用完，反而由于多开窗口触发了限制。
四点前我还是睡了。
一方面是累了，一方面他的速率限制也有点频繁。当时用了50%还是70%来着，具体的数字忘了。
总之就这么到了四月份。
游戏地图依然还是2d 的，但看上去完成度高得多。这里已经可以算是demo1.0 了。
点按士兵出现移动范围，正常的地图画面，还有城池的子界面。征兵，建设，装备
最先完成的是征兵设计，从金币池改成了人口池。增加了武将选择，数值设计，至于技能和其他的是原先就有的。
9号的时候我就打算转3D 了，但各方面又还没完全做完。
当时我一直在处理基本的士兵移动逻辑。
最开始很简单，点按士兵行动，然后再点敌人攻击。屏幕右下角可以按技能。
但这又很奇怪，于是我打算把按键整合到右键。右键士兵就可以移动，攻击，技能。
做完后，发现整个链路太繁琐，于是我又去看三国志11的，这才发现自己忘了很多东西。
三国志11有两条链路，一是可以直接点击敌方或是地格，进入到委托状态。
委托状态会自动在我方回合结束时执行任务。
另一种就是直接点击士兵，移动后弹出菜单，然后执行攻击技能指令
于是我把这两个逻辑结合起来了。
假如在移动范围外，就进入到委托状态。
假如移动范围内，就进入到攻击状态。
好吧这方面的问题实在困了我很久。然后还有城市的 ui，之前改 ui 的时候忘了 gpt 是能直接看图的，所以改了很久也不太行。
额反正开发体验基本上是想一出是一出，其实就是仿三国志11的小游戏。
glm-5，使用体验非常的差，我是在 trae 上用的，workbuddy 上拿来处理一些简单的内容，几乎从来不用它改代码。
但是后面实在是没办法了，claude 的（windsuf） 免费额度用完，gpt 的又没有好的中转站了。
于是便试了试 trae，其实国际版的 trae 表现还不错，就是不知道为啥绑不了信用卡，按照他们说的改港区注册账号也不行。
于是后面用国内的 trae，免费归免费，但是体验真挺一般的。完全不知道能做些什么，最终东西还是由 claude 来做的。
前端审美能力也很差，一个问题理解不了反复的改。
不过有一说一
在用 workbuddy 一段时间后。
我意识到 agent 的能力确实很强，很多事情都给可以慢慢扔给它。
以前那种慢慢的磨合节奏没有必要，ai 是真的扩展人类边界了。
就和手机一样，有了手机之后你就不需要去记地图，去打电话，去思考交通，同时也有很多便利。
我觉得需要最大限度的利用这份能力
github 上的大部分项目都可以作为现有的 ai 能力的边界去使用。
一些简单的项目功能，甚至是学习一些东西。
像是在 ai 使用上 什么2api 之类的反代或者是其他的工具插件。
用通用 agent 部署下来，然后他自己也会查找原因，非常方便。
当然最初我用的时候，trae 并没有浏览器控制（这个的话好像是有但是我确实是没用），和相关的图片解析功能。
于是我先搭了一套反代的，配置了一个域名邮箱，但是不知道卡在哪个环节了。总之调用不了域名邮箱。
也有可能是项目的问题。
不过我细想一下，似乎 kiro 也确实不好反代。需要绑卡。总之后面我搁置了这个计划。
不小心应用 codex 的调整了，导致代码现在直接被覆盖。
…月…日
我靠真的有点无语，我感觉文件是恢复不回来了。
好吓人，最终恢复回来了
差点被我一键清空。
最近用的中转站非常好，虽然不知道为什么，但是本来是有限制的，又给我变成无限额度了，爽蹬中。
进度当然也并没有很快，由于前面各种乱七八糟的问题，先把基本的功能做完，然后开始修架构上的问题
像是什么结束回合和快进的相关性能问题，地图加载，还有一些 ui 的毛病，一些之前还未落地的功能。
之后就是不断的拆分文件，拆分逻辑
codex 还是很强的，虽然前端方面依然有问题，但是一些小毛病解决的很快。
在这个基础上我反而焦虑了不少
因为我发现自身对于 ai 的边界没有一个清晰的了解，同时也不清楚 godot 的相关能力。
所以很多时候都是一脸懵，完全是把 codex 当许愿机来用。
所以在 codex 的使用上非常原始。
godot 的 mcp 连接上能读取日志。像是这种内容我做游戏之前完全没想过。
把 codex 读取不了日志这一行为当成了默认。
这件事情本身让我意识到，ai 确实很强大，最初我承认只是想做点简单的小玩具。
但是后面我发现他的能力确实很可观。
不过即使是这样，也做不到那种自我迭代的程度。
人类得去辅助他学习想做的项目方面的知识。
同时应对自身项目出现的问题，应该相信 ai 的能力让他试着先去解决看看。
有很多通用性的插件 mcpskill 其实根本没必要装，因为真有用官方马上用上了。
比如说最近很火的 goal 模式， codex 端上来反响很好，马上 claudecode 就跟上了。
像是这种内容在现在的 ai 发展上很常见。
然后由于我没什么项目规划，做这个也本来就是为了实验
在不清楚有那些地方有问题的时候，我便选择了修复 bug 和一致性的问题
（说实在的，不清楚代码劣势确实很大，生成出来的内容完全不懂，造了个黑箱出来，也不清楚怎么运行的。）
不断的优化架构，性能，以及之前的一些遗留物，还有具体的游戏界面
其实现在 ai 在很多游戏引擎上的表现并不好，毕竟是给人用的，而不是给 agent 用的，本质上来说很多功能都还是太不适应了。
然后就是 ai 在代码上能力的突飞猛进，很多时候与其花很多时间抽卡去修 bug，不如等待更新更强的 ai
其实就这样吧，也没多少能说的了。
最近一波codex充日活，然后疯狂限免，但我还是没买，claude的话不必多说，价格又贵中转也少，还会封号。
至于国模的话，kimi没试过，在kimi3出来之前都很路边。glm5.2倒是挺多地方可以薅，所以也没买过专门的套餐。ds 的话一般是用来跑黄文的，所以自然也不在考虑范围内。
