# User Mode File System
Dokan is a user mode file system for Windows.  
It allows anyone to safely and easily develop new file systems on Windows operating systems. 
[Getting Started](https://github.com/dokan-dev/dokany/blob/master/README.md)

## Data as file
Easily mount any kind of data as a virtual file and access it transparently from all your Windows applications. It can literally be anything: files from other locations, stored locally or remotely in the cloud... Creativity will be your limit. 
![](http://dokan-dev.github.io/images/walnut.png)
## Access Control
Working in user mode has several benefits and access control is one of them. You can have complex and custom access checks even with multiple security layers if you want to.
![](http://dokan-dev.github.io/images/walnut.png)
## Be safe
**Dokan** takes care of the hard stuff and you never have to go deeper into kernel mode. This means you can develop your driver safely without having to fear BSOD at any test. **Dokan** code is available online since 2007. While people came and left the code remains alive thanks to the open source community.
* * *
## Driver. Don't.
When you want to create a new file system on Windows you need to develop a file system driver. Developing a device driver that works in the kernel mode on Windows requires highly technical skills.  
By using Dokan, you can create your own file systems very easily without writing device drivers. Dokan is similar to FUSE (Linux user mode file system) but works on Windows. 
![Blue Screen of Death in Windows 10](http://dokan-dev.github.io/images/bsod.png)

## User-mode API. As you like.
Dokan User-mode API provides functions to mount/unmount your driver and several callbacks to implement on your application to have a fully working user mode file system driver.
Additionally to the default provided [C](https://github.com/dokan-dev/dokany/) library, the API is also available for [DotNet](https://github.com/dokan-dev/dokan-dotnet), [Java](https://github.com/dokan-dev/dokan-java), [Delphi](https://github.com/dokan-dev/dokan-delphi) and [Ruby](https://github.com/dokan-dev/dokan-ruby). 
* * *
## FUSE Wrapper.
[Dokan FUSE](https://github.com/dokan-dev/dokany/wiki/FUSE) (Filesystem in Userspace) is a wrapper library that makes Dokan compatible with FUSE API. You simply need to rebuild your FUSE source code without changes with Cygwin/MinGW and link against the library to make it work on Windows. Now available by default in the main source repository and installers.

## Frequently Asked Questions
####  [What is the story of Dokan?](http://dokan-dev.github.io/#collapse1)
The Dokan Library project was originally created and maintained by Hiroki Asakawa from 2007 to 2011.  
It has been maintained from 2011 to 2014 by the community with different fork.  
Since 2014, the project is highly maintained by Adrien J. and Maxime C. with the fork Dokany and gracefully code signed by the company **ISLOG**. 
####  [Will Dokany be frequently maintained?](http://dokan-dev.github.io/#collapse2)
Dokany is **[highly maintained](https://github.com/dokan-dev/dokany/graphs/contributors)** since it starts. The community is growing and number of contributors (that we ) are also growing every day. 
####  [Which Operating Systems are supported?](http://dokan-dev.github.io/#collapse3)
You can find a full list of supported operating system **[here](https://github.com/dokan-dev/dokany#environment)**. 
####  [What's new since Dokan first name?](http://dokan-dev.github.io/#collapse4)
Until version 0.7.4, Dokany focused to improve and fix Dokan 0.6.0 (by Hiroki Asakawa) without breaking compatibility. You can find the full change log **[here](https://github.com/dokan-dev/dokany/releases)** But in simple words: A lots of fixes, more stability and it is much more near of a real file system than ever. 
####  [Is Dokany ready for a commercial product?](http://dokan-dev.github.io/#collapse5)
**It is !** There are still a few things `not available yet` and on the roadmap but these are well documented today on github so if you don't need it, you should be fine. If you do commercial products based on Dokany, please be sure to **[respect licenses](https://github.com/dokan-dev/dokany#licensing)** and `be fair` if it becomes a success, it is always appreciated being **[supported](http://dokan-dev.github.io/#supportus)** for an open source projects. 
####  [What is ISLOG’s relationship to Dokany?](http://dokan-dev.github.io/#collapse6)
The project is supported by **ISLOG** company which provide tools, driver certificate for releases, and other kinds of development materials. The project is used internally by our company so some features and bug fixes was developed at our business time, but the project is a personal initiative and mainly supported at personal time.
