#  [#](https://xugaoyi.com/pages/4643cd/#js%E8%AE%BE%E8%AE%A1%E6%A8%A1%E5%BC%8F%E6%80%BB%E7%BB%93%E7%AC%94%E8%AE%B0) JS设计模式总结笔记
##  [#](https://xugaoyi.com/pages/4643cd/#%E5%BC%80%E7%AF%87-%E5%89%8D%E7%AB%AF%E5%B7%A5%E7%A8%8B%E5%B8%88%E7%9A%84%E6%88%90%E9%95%BF%E8%AE%BA) 开篇：前端工程师的成长论
能够决定一个前端工程师的本质的，不是那些瞬息万变的技术点，而是那些**不变的东西** 。
所谓“不变的东西”，就是**驾驭技术的能力** 。
具体来说，它分为以下三个层次：
  * 能用健壮的代码去解决具体的问题；
  * 能用抽象的思维去应对复杂的系统；
  * 能用工程化的思想去规划更大规模的业务。


> 基础理论知识是一个人的基线，理论越强基线越高。再为自己定一个目标和向上攀附的阶梯，那么达到目标就是时间问题，而很多野路子工程师搞了半辈子也未达到优秀工程师的基线，**很多他们绞尽脑汁得出的高深学问，不过是正规工程师看起来很自然的东西** 。—— 吴军
##  [#](https://xugaoyi.com/pages/4643cd/#%E8%AE%BE%E8%AE%A1%E6%A8%A1%E5%BC%8F%E4%B9%8B-%E9%81%93) 设计模式之“道”
  * 设计模式是“拿来主义”。如使用数学公式，不会从头推导一个公式。


###  [#](https://xugaoyi.com/pages/4643cd/#%E6%A0%B8%E5%BF%83%E6%80%9D%E6%83%B3) 核心思想
  * 设计模式的核心思想——**封装变化**
  * 保证可维护性、可扩展性。
  * 将变与不变分离，确保变化的部分灵活，不变的部分稳定。——这就是所谓的“健壮”的代码。


##  [#](https://xugaoyi.com/pages/4643cd/#%E8%AE%BE%E8%AE%A1%E6%A8%A1%E5%BC%8F%E4%B9%8B-%E6%9C%AF) 设计模式之“术”

##  [#](https://xugaoyi.com/pages/4643cd/#%E5%B0%8F%E7%BB%93) 小结：
  * 创建型模型封装了创建对象过程中的变化。
  * 结构型模式封装了对象之间组合方式的变化。目的在于灵活的表达对象间的配合与依赖关系。
  * 行为型模式将对象千变万化的行为进行抽离，确保安全、方便的更改。


##  [#](https://xugaoyi.com/pages/4643cd/#%E5%88%9B%E5%BB%BA%E5%9E%8B-%E5%B7%A5%E5%8E%82%E6%A8%A1%E5%BC%8F-%E7%AE%80%E5%8D%95%E5%B7%A5%E5%8E%82-%E5%8C%BA%E5%88%86-%E5%8F%98%E4%B8%8E%E4%B8%8D%E5%8F%98) 创建型：工厂模式-简单工厂——区分“变与不变”
先了解构造器模式，在JS中的构造函数即构造器。使用构造函数，即使用构造器模式。
###  [#](https://xugaoyi.com/pages/4643cd/#%E6%9E%84%E9%80%A0%E5%99%A8%E6%A8%A1%E5%BC%8F) 构造器模式

```
function User(name, age, career){
  this.name = name
  this.age = age
  this.career = career
}
const user = New User('张三', 18, '前端工程师')
```

###  [#](https://xugaoyi.com/pages/4643cd/#%E7%AE%80%E5%8D%95%E5%B7%A5%E5%8E%82%E6%A8%A1%E5%BC%8F) 简单工厂模式

```
function User(name , age, career, work) {
    this.name = name
    this.age = age
    this.career = career
    this.work = work
}

// 工厂函数 （将变的部分抽离出一个函数）
function Factory(name, age, career) {
    let work
    switch(career) {
        case 'coder':
            work =  ['写代码','写系分', '修Bug']
            break
        case 'product manager':
            work = ['订会议室', '写PRD', '催更']
            break
        case 'boss':
            work = ['喝茶', '看报', '见客户']

        // 其它工种的职责分配
        //case 'xxx':
            //...

    return new User(name, age, career, work)
}

```
